# Manim 渲染插件 · 顶层设计

> 本文只写目标、方案、取舍与决策；文件级执行步骤等实现开始时另立 Step 文档。

## 1. 它是什么

给宿主加一个能力：**AI 在聊天里直接写 Python 的 Manim 代码，当场渲染出画面**。只装这一个插件就能用——不需要黑板，也不需要其他任何插件。

它把旧黑板里三件事合成一个包：

- **运行时**：用真 Python（Pyodide，CPython 编译成 WASM）执行 AI 写的 Manim Python（旧黑板是自写 `src/core/py-*` 转译器，已弃用——见 §7.5、§7.6）。
- **渲染器**：把运行时动作落到真 manim-web 上，画进一块画布（旧 `src/engine/*`）。
- **入口与出口**：Host 工具（AI 怎么把代码交进来）+ 聊天流卡片（用户在哪看到）。

## 2. 独立运行判据（硬要求）

用户原话：「它应该要独立运行，我们以后的包都是这样，否则拆了没有意义。」

**判据**：模块表里没有黑板、没有播放内核、没有 tts 时，AI 仍能调工具提交一段 manim Python，聊天流里出现一张能看、能重跑的卡片。

由此推出三条边界：

- 不依赖黑板的数据模型（Deck / Scene / Step）、store、相位状态机；
- 不依赖 tts（旁白是黑板的事）；
- 卡片的容器、错误显示、生命周期自己管。

## 3. 既有的家底与必须补的缺口

| 段 | 旧黑板里的家底（`plugins/blackboard.bak/src/`） | 搬运性 |
|---|---|---|
| 执行 | `engine/canvas.ts`（`new Function` 执行原语）、`engine/library.ts`（manim-web 懒加载单例）、`engine/preview.ts`（隐藏容器校验 + 截图） | 可搬，需自带容器 |
| 渲染 | `engine/renderer.ts`（常驻画布 + 串行队列 + 固定 1280×720 + 截图） | 可搬 |

已核对源码的事实：

- 旧黑板的手写转译器链（`core/py-tokenizer.ts`、`py-parser.ts`、`py-codegen.ts`、`py-transpile.ts`、`precheck.ts`）**不再搬运**——它只能覆盖「撞到才补」的语法子集，缺口补不完（实测 33 次工具调用仅 5 次成功，86% 失败是语法缺口）。改用真 Python 运行时后标准 Python 3 语法与库都由解释器保证（见 §7.5、§7.6）。
- 新的运行时链在 `src/core/py/`：`runtime.ts`（Pyodide 装载/执行/错误归一）+ `manim-shim.ts`（Python 侧 manim 适配层 + construct 的 async 改写）+ `bridge.ts`（契约）+ `manim-bridge.ts`（真桥）/ `dry-run-bridge.ts`（预检空桥）+ `api-map.generated.ts`（探针实测三态表）。无 DOM、无宿主依赖。
- `renderer.ts` **不 import** deck / stores / status；它的入口本就是 `initRenderer(container: HTMLDivElement)` ——容器由外部给。所以独立运行不缺容器，缺的是「谁来调它」。
- 旧黑板里串起这块的是**别处的四件事**：`host/tools.js` 的工具入口、`playback/narration.ts` 的推进泵、`engine/sandbox.ts` 的校验触发、`host/stepGate.js` 的回执闸。

**缺口 = 触发入口 + 卡片 + 容器生命周期**，这三件旧黑板里由播放内核承担，本插件必须自己补。

## 4. 对外的两个面

| 面 | 形式 | 内容 |
|---|---|---|
| AI 侧 | Host 工具 | `manim_render`：入参是一段 manim Python，出参是预检结果；预检不过原样回 `{ok:false,error}`，让 AI 同轮自我修正 |
| 用户侧 | 聊天流卡片 | `conversation.chat.node` 槽位：挂载画布、显示预检问题与渲染错误 |

**数据契约**：一次调用 = `{ python: string; callId: string }`。旧模型里对应的字段是 `Step.manim`，也就是这块只是把「步」的外壳去掉，留下代码本身。

## 5. 对外服务（关键：将来黑板靠这个接）

机制：一个插件 `ctx.provide('<服务名>', 服务对象)`，别的插件用 `ctx.get('<服务名>')` **软可选**消费；插件之间禁止 import，所以黑板将来只能用这条路接（仓内先例：`tts` 插件提供、`speak-message` 与黑板消费）。

**要 provide 的（就两件）**：

1. **运行时**：`check(python) -> { ok: true } | { ok: false, error }` —— 干跑预检（空桥）。黑板不该再自己校验一份。
2. **画布**：`createSurface(container) -> Surface`，`Surface` 上 `run(python)` / `dispose()` —— 一块可挂载的画布，挂到调用方给的容器里。

> 落地情况（2026-10-09）：两件都已在 Client 半边 `ctx.provide('manim', …)`（`plugins/manim-renderer/src/client/service.ts`）。
> `createSurface` 原设计的 `opts?` 暂不做——现在没有调用方需要它，加了就是死参数；等黑板提出具体选项再加，签名向后兼容。

**不 provide 的**：

- 卡片 UI 与槽位注册（黑板有自己的舞台形态）；
- Host 工具面（工具是各插件自己的 AI 入口）；
- 分步播放、播放头、旁白（黑板自己决定何时喂下一段、怎么念）。

服务名与签名见 §8（已定稿）。

## 6. 将来接入黑板的分界线

**谁拥有画布，谁负责播放。** Manim 插件给「运行时 + 一块画布」，黑板给「分步、播放头、旁白、步同步闸」；黑板用软可选依赖消费，服务缺席就退化成没有画布，不报错、不阻塞。

## 7. 取舍与决策

1. **服务按「能力」切，不按模块切**：对外只露「运行时」和「画布」两件事，内部的 Python 运行时 / 适配层 / 桥不外露。
2. **卡片自己带**，不交给黑板——否则独立运行不成立；这也是对外服务里不含 UI 的原因。
3. **回执闸后置**：独立插件没有「下一步」，第一版不做「AI 等画面渲完再往下写」；但 `Surface.run()` 返回 Promise，闸将来在黑板那侧接同一个完成事件即可，接口现在预留。
4. **运行时不做跨次持久化**（2026-10-09 定）：每次执行都是一个独立模块，一段代码执行完变量即消失；同一块画布要连续跑多段代码时，"上一段的变量这一段引用"由**调用方**组织（拼成一段、一次执行），运行时只做单段执行。理由：一张卡 = 一段代码的独立场景，不该被别处的分步模型绑住。
5. **换用现成运行时，不自己写编译器**（2026-10-09 定）：原计划搬旧黑板的手写 Python→JS 转译器，实测发现它是「撞到才补」的子集，33 次调用仅 5 次成功、86% 失败属语法缺口，永远补不完。先用 **[Skulpt](https://skulpt.org/)（纯 JS 的 Python 3 解释器，559KB / gzip 139KB）**替掉了转译器：标准 Python 3 语法由解释器保证，我们只维护「Python 侧 manim 适配层 + 桥」。
6. **运行时再换成 Pyodide（真 CPython）**（2026-10-09 定）：Skulpt 解决了**语法**，但解决不了**库**——它没有 numpy，只能在 `numpy-shim.ts` 里手写子集。而 Manim 代码里 `np.linspace` / 向量运算遍地都是，手写子集同样是「撞到才补」，补不完（实测轨迹里 `UP * 0.2` 一类静默算错就是它导致的）。改用 **[Pyodide](https://pyodide.org/)（CPython 编译成 WASM）**：numpy 就是真 numpy（随包 wheel，2.0.2），以后要 pandas / scipy 也只是多放一个 wheel。代价是资产体积（核心 + numpy ≈ 18MB，随包放 `assets/pyodide/`，不走 CDN、不依赖外网）与一处机制改写：CPython 无法在同步函数中途让出控制权，`construct` 由 `ast` 改写成 `async def` 并给 `play` / `wait` 补 `await`。**Skulpt 与 numpy-shim 一并删除**，两端（Host 预检 / Client 渲染）共用同一份真 Python。

## 8. 已定决策（2026-10-09，用户拍板）

| # | 事项 | 定案 |
|---|---|---|
| 1 | 包名 | `manim-renderer` |
| 2 | 客户端服务名 | `manim`；方法面就 §5 那两件（`check` + `createSurface`） |
| 3 | Host 工具名 | `manim_render`，入参 `{ python }` |
| 4 | 首版粒度 | 一张卡 = 一段代码（可重跑）。追加多段累进**不做**——那属于黑板的分步播放 |
| 5 | 运行时 | 换用 Pyodide（真 CPython + 真 numpy）；经 Skulpt 过渡后落地，弃用手写转译器与手写 numpy 子集（§7.5、§7.6） |
