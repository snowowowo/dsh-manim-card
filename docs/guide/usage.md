# 在聊天里用

本页覆盖聊天流中动画卡片的全部行为：卡片如何产生、何时自动播放、手动播放怎么做、代码怎么看、mp4 怎么导出，以及环境不满足时卡片如何提示。怎么装见[安装](/guide/installation)。

## 卡片的产生

在会话中向 AI 提出「用 Manim 绘制……」，AI 通过 `manim_render` 工具提交一段 Python 代码。工具返回前会先在 Node 侧的真解释器里干跑一遍：

- 语法错误、未定义名称、manim-web 实测缺失的写法，立即以 `error` 返回，模型在**同一回合**按行号自我修正，不会在聊天里留下空白或残缺卡片；
- 通过预检的代码才写进会话，卡片随之出现在聊天流中。

渲染成功后卡片停留在终态画面；渲染期失败时，卡片底部显示 manim 的原始错误信息。工具本身的契约（入参、返回、预检边界）见[宿主工具](/api/tool)。

## 自动播放规则

聊天流中可能同时存在多张卡片，全部完整播放开销较大，因此仅以下情形完整播放：

| 情形 | 行为 |
| --- | --- |
| 新生成的卡片首次进入视口 | 完整播放一次 |
| 之后的任何重新挂载（切回会话、刷新页面、滚出后再滚回） | 直接落至末帧，不重演 |
| 历史会话中的卡片 | 不播放，直接显示终态画面 |
| 同一 step 内并行产生的多张卡片 | 仅完整播放最后一张 |
| 滚出视口 | 不销毁画布；活跃画布超过 8 张时，按距阅读位置由远及近回收（浏览器 WebGL 上下文数量有上限） |

::: warning 播放机会只消耗一次
机会在决定时即记录：进入播放队列后滚出视口、或播放中途跳过，机会均已消耗，再次查看时显示的是末帧，不会从头重播。此设计用于避免滚动导致重复播放。
:::

## 手动播放

卡片顶栏的播放按钮有两种状态：

- **▶**：完整播放。优先于上述全部自动规则——包括已经被判定为「落末帧」的卡片。
- **⏩**：直接落至终态。

被中断的卡片（回合被停止）默认不自动渲染，需按 ▶ 手动渲染。同一页面的所有画布共享一条 Python 执行队列，因此一个页面内不存在两块画布同时播放。

## 导出 mp4

卡片头部的下载按钮把该段源码交给**本机安装的 manim 命令行**真实渲染，产物保存至「下载」文件夹。这是本插件唯一走本机环境的路径，与卡片渲染用的浏览器运行时无关。

- **按钮可用性取决于本机环境**：需要 `python3` / `manim` / manim 库 / `ffmpeg` 四项，缺失项在悬停提示中逐条列出；`latex` 与 `dvisvgm` 仅公式写法需要，不属于必要条件。
- 导出成功后悬浮显示「在文件夹中显示」，点击可在系统文件管理器中定位该文件。
- 导出记录持久保存：页面刷新后卡片仍显示「上次导出的文件」；文件被删除时也如实显示。
- 本机需要装什么、怎么检查，见[设置面板](/guide/settings#本机环境)。

## 环境不满足时的提示

画面出不来时，原因通常不在代码，而在机器的条件。卡片会在这类失败下补一条可执行说明，与本插件其余两处的措辞同源：

- 卡片底部的错误行下方多一行提示（仅在确有硬性未满足项时出现，正常环境看不到）；
- 实验场状态条上对应的那枚 chip 可以点开，见[实验场](/guide/lab#环境状态条)；
- 设置面板的「浏览器运行时」卡逐项列出状态与处置，见[设置面板](/guide/settings#浏览器运行时)。

三处读的是同一份判定结果，由核心包给出，措辞不会互相打架。要在自己的插件里读这份状态，用 [manim-live 服务的 environmentStatus()](/api/service#manim-environmentstatus)。
