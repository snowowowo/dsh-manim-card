# 实验场

实验场在左侧导航的「Manim 渲染」页面，是本插件功能的验收台：卡片渲染、播放控制、查看代码、导出 mp4、预检报错，都在这里对照着验。本页讲它的界面、环境状态条、样例模式、工具条与进度保存。

实验场不是独立实现的调试页——**画布与聊天卡片使用同一组件**，因此手动播放、查看代码、导出等能力与聊天内完全一致，验过的行为可以等价地认为在聊天里成立。

样例是**内置**的一小集（打进插件，正式安装里同样可用）。239 条那套语料回归网由核心包 [manim-live](https://github.com/snowowowo/manim-live) 仓承担（`corpus/`），本插件不维护语料。

## 界面

- 左侧为样例清单，右侧为渲染预览：点任一条即渲染，通过 / 未通过状态即时标注在条目上。
- 页面顶部提供两种模式：**样例**与**自定义代码**（自由编写并运行一段 Python）。
- 页头下方常驻一条环境状态条，见下。

## 环境状态条

状态条回答一个问题：**这台机器还缺什么**。它把「能不能出画面」与「能不能导出 mp4」两组条件并排摆出来，四枚 chip：

| chip | 管什么 | 取值 |
| --- | --- | --- |
| 本机 Manim | 导出 mp4 走的那套本机工具 | 检测中 / 就绪 / 缺 N 项 / 未知 |
| 运行时 | Python 运行时（Pyodide） | 未加载 / 加载中 / 就绪 / 失败 |
| 公式样式 | KaTeX 样式表 | 未配置 / 加载中 / 已加载 / 失败 |
| 浏览器能力 | WebAssembly / WebGL / 屏幕录制 | 就绪 / 缺 N 项 |

**只有不满足的那一枚可以点开**；满足的是纯标签。点开是同一块面板，说的是同一件事：这台机器上所有待处理项逐条列出（浏览器侧那几句由核心包给出，本机侧写明缺哪几项），下面是能立刻做的动作。

- **立即预热**：只在运行时为「未加载」或「失败」时给出。第一次渲染要等约 13 MB 的运行时取完，预热掉的就是这段等待；按了之后有回执（成功说「运行时已就绪」，失败给出原因），因为预热本身没有画面反馈。
- **重新检测**：只在本机环境缺项或问不到时给出，再问一次本机环境。
- 面板可以关闭；「未加载」与「未配置」都不是错误，只是「还没有」，所以它们不出现在错误色的提示里。

读数的刷新方式两边不同，因为数据来源不同：

- **浏览器侧**随状态变化**自动刷新**——运行时阶段、取包结果、公式样式加载结果任一变动都会播一次；
- **本机侧**在进入页面时问一次、按「重新检测」再问一次。Host 侧带缓存，因此几十张卡同时问也只跑一遍探测。

三处（状态条、设置面板、聊天卡片）读的是同一份判定结果，由核心包给出，措辞不会互相打架。

## 样例模式

样例集约十条，覆盖基础图形、变换、坐标系与曲线、`MathTex` 公式、文字列表、柱状图、`TracedPath` 轨迹、3D 场景，以及**一条应当被预检拒绝的坏代码**。

- 每条样例左侧有状态点：未跑（空心）/ 通过（绿）/ 未通过（红）。
- 点中一条后，预览上方显示该样例的**预期**（一句话「应该看到什么」），人工验收对着它看。
- 通过判定：普通样例渲染成功即通过；标注「应当被拒绝」的那条**反过来**——渲染失败才算通过，它验的正是「预检当场报错并说明原因」。

## 自定义代码模式

自由编写一段 Manim Python 并运行，用于验样例之外的写法。与聊天里的代码口径一致：完整 `class` 外壳与裸 `construct` 体两种形态都收；渲染期错误原样显示，不经过工具那道预检。

## 工具条

| 控件 | 作用 |
| --- | --- |
| 停止 | 中断当前渲染 |
| 清除记录 | 清掉逐条结果与状态点 |
| 极速 | 不等待 `run_time` 与 `wait`，直接落至终态。切换开关会把当前条按新口径重跑一遍；updater 驱动的轨迹仍会被推进，不会变成空的 |
| 清除已下载的库 | 删掉本机缓存的第三方包，用于重验「首次取包」的过程。见[设置面板](/guide/settings#包缓存) |

## 进度保存

逐条结果、极速开关、自定义代码、当前模式均存入 localStorage，刷新或中断后可从断点继续。
