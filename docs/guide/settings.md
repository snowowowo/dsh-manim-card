# 设置面板

宿主设置中的「Manim Card」一节回答两个问题：**渲染需要什么**与**导出需要什么**，另加一块**Python 库**（离线可用性取决于哪些包已在本地）。页面按「环境」分组加一张独立的库清单卡组织：

| 分组 / 卡片 | 回答的问题 | 数据来源 |
| --- | --- | --- |
| 环境 → 浏览器运行时 | 这一页能不能出画面、能不能在浏览器里导出视频 | 当前页面（核心包的环境状态） |
| Python 库 | 哪些第三方库已经在本地 | Host 路由 + 本机缓存目录 |

两块都读当前页面或本机缓存，**没有一块与本机的 Manim 安装有关**——渲染与导出都发生在浏览器里，本机不需要装任何东西。

## 浏览器运行时

运行时本身与四项浏览器条件收在一张卡片里。数据取自**当前页面**而不经 Host：这些事发生在浏览器里，Host 问不到。

| 行 | 取值 | 说明 |
| --- | --- | --- |
| Python 运行时 | 未加载 / 加载中 / 就绪 / 失败 | 「未加载」是正常的初始状态——第一次渲染前要先取约 13 MB 的核心。失败时 ⓘ 里是错误原文与当前取数地址 |
| 公式样式 | 未配置 / 加载中 / 已加载 / 失败 | 「未配置」指创建渲染器时没传 `katexBaseURL`，此时 `MathTex` / `Tex` 仍会渲染，公式却是无样式的裸排版。本插件始终传，所以这里只会是「已加载」或「失败」 |
| WebGL | 是 / 否 | 画面本身的出口，没有它卡片渲染不出任何东西 |
| WebAssembly | 是 / 否 | Python 解释器的运行基础，没有它所有渲染都起不来 |
| 浏览器导出 | 是 / 否 | 有它才能把卡片导出成视频文件（WebCodecs 或 MediaRecorder）；缺它只影响导出，渲染不受影响 |

卡片头部的说明行给出待处理项计数（全满足时显示「全部就绪」）；有未满足项时，卡片底部逐条列出**可执行的处置**，例如「当前浏览器没有可用 WebGL：manim-web 出不了画面」「Pyodide 运行时启动失败：… 先确认取数地址真能打开、其下文件完整」。这些句子由核心包按同一份口径给出。

各字段的取值语义与类型定义见[数据类型](/api/types#environmentstatus)。

::: info 导出不需要本机环境
导出走的是浏览器逐帧编码，与卡片同一个渲染引擎——所以这里没有「本机装没装 manim / ffmpeg / LaTeX」这一栏：那些与本插件无关。判定的口径写在上面「浏览器导出」一行的 ⓘ 里，卡片上导出按钮的可用性用的是同一份结论。
:::

## Python 库

列出常用的十一个库（numpy / sympy / mpmath / matplotlib / pandas / scipy / scikit-learn / statsmodels / networkx / pillow / opencv-python），每行为「状态点 + 名称 + 本机占用 + 一个操作键」：

| 状态点 | 含义 | 提供的键 |
| --- | --- | --- |
| 绿实心 | 已缓存到本机 | 删除 |
| 灰实心 | 随包内置 | 无（显示「内置」） |
| 空心环 | 未缓存 | 缓存 |

未缓存的那一行按「缓存」会把该库连同依赖一起取回。

用词为「缓存」而非「下载」：这些包本来就是运行时按需联网获取的（首次 `import pandas` 时自动获取一次，经 sha256 校验后存入 `~/.dsh/cache/manim-live/pyodide/`），此处操作是**提前缓存到本机**，以保证之后断网可用。进度与失败原因也一并进环境状态：取包期间卡片上显示「正在加载 X…」，失败则进「浏览器运行时」卡片底部的处置句——渲染期取包失败读的是同一句话。

清单下方提供**「缓存其他库」**卡片：输入任意包名即可获取（`Pillow`、`scikit_learn` 等写法均可识别，输入时显示补全建议）；已获取的手输包会保留在清单中，获取与删除在同一路径完成。
