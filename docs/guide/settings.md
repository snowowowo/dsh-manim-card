# 设置面板

宿主设置中的「Manim 渲染」一节回答两个问题：**渲染需要什么**（浏览器侧的运行时、公式样式与能力）与**导出需要什么**（本机安装的 Manim 环境），另加一块**包缓存**（离线可用性取决于哪些包已在本地）。本页按这三块讲。

## 浏览器运行时

运行时本身与四项浏览器条件收在一张卡片里，数据取自**当前页面**而不经 Host：这些事发生在浏览器里，Host 问不到。

- **Python 运行时**：未加载 / 加载中 / 就绪 / 失败。「未加载」是正常的初始状态——第一次渲染前它会先下载约 13 MB 的核心，失败时 ⓘ 里是错误原文与当前取数地址。
- **公式样式**：未配置 / 加载中 / 已加载 / 失败。未配置指创建渲染器时没传 `katexBaseURL`，此时 `MathTex` / `Tex` 仍会渲染，公式却是无样式的裸排版；本插件始终传，所以这里只会是「已加载」或「失败」。
- **WebGL**：画面本身的出口，没有它卡片渲染不出任何东西。
- **WebAssembly**：Python 解释器的运行基础，没有它所有渲染都起不来。
- **屏幕录制**：只影响「浏览器直接录屏」这一种导出方式，缺它不影响渲染与导出 mp4。

有未满足项时，卡片头部显示待处理项计数，卡片底部逐条列出**可执行的处置**（例如「当前浏览器没有可用 WebGL：manim-web 出不了画面」「Pyodide 运行时启动失败：… 先确认取数地址真能打开、其下文件完整」）。这些句子由核心包按同一份口径给出，设置页与实验场状态条用的是同一套。

## 本机环境

逐项探测 `python3` / `manim` / manim 模块 / `ffmpeg` / `latex` / `dvisvgm`，每项给出 **ok / 缺失 / 出错** 三种状态。每行显示「名称 + ⓘ + 状态点与版本」；该项的用途、探测位置与实际执行的命令收纳在 ⓘ 中（悬浮或键盘聚焦时显示）。头部提供「重新检测」。

- 探测**在用户打开面板时才执行**，逐项串行、各有超时，不在启动时扫描机器。
- 探测会自行补齐 PATH：桌面端宿主拿到的 PATH 经过裁剪，`/usr/local/bin` 等路径常不在其中，不补齐会误报「已安装但检测不到」。
- 「manim 库」项跟随 manim 命令定位解释器：若命令是软链至某个 venv 的，按 PATH 上第一个 `python3` 判断必然误报。

## 包缓存

列出常用的十一个库（numpy / sympy / mpmath / matplotlib / pandas / scipy / scikit-learn / statsmodels / networkx / pillow / opencv-python），每行为「状态点 + 名称 + 本机占用 + 一个操作键」：

- 绿实心 = 已缓存，灰实心 = 随包内置，空心环 = 未缓存；
- 未缓存的提供「**缓存**」键（连同依赖一起获取）；已缓存的提供「**删除**」键；随包内置的显示「内置」（禁用）。

用词为「缓存」而非「下载」：这些包本来就是运行时按需联网获取的（首次 `import pandas` 时自动获取一次，经 sha256 校验后存入 `~/.dsh/cache/manim-live/pyodide/`），此处操作是**提前缓存到本机**，以保证之后断网可用。

清单下方提供**「缓存其他库」**卡片：输入任意包名即可获取（`Pillow`、`scikit_learn` 等写法均可识别，输入时显示补全建议）；已获取的手输包会保留在清单中，获取与删除在同一路径完成。
